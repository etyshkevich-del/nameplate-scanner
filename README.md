# Local AI: шильдик → Excel и RAG

Локальное Android-приложение с двумя независимыми сценариями:

- распознавание шильдика электродвигателя и заполнение Excel-шаблона;
- вопросы по одному или нескольким PDF/DOCX с отдельными диалогами.

Фотографии, документы, история чатов и ответы обрабатываются на устройстве. В
приложении нет серверной части и разрешения на доступ в интернет.

## Возможности

### Фото шильдика → Excel

1. Пользователь снимает или выбирает фотографию.
2. Gemma-4 E2B извлекает девять паспортных характеристик в JSON.
3. Значения можно проверить и отредактировать.
4. `WorkbookWriter` записывает их в `C3:C11` исходного `template.xlsx`, сохраняя
   структуру и оформление книги.

### Локальный RAG по документам

1. В один диалог можно подключить несколько PDF/DOCX.
2. PDF разбирается через PdfBox-Android, DOCX — потоковым чтением
   `word/document.xml`.
3. Текст делится на перекрывающиеся фрагменты примерно по 1250 символов.
4. Локальный индекс ранжирует фрагменты по BM25, словоформам, четырёхсимвольным
   совпадениям и небольшому словарю синонимов.
5. До шести лучших фрагментов передаются Gemma вместе с вопросом.
6. Ответ сохраняется в истории нужного диалога и отображается с базовым Markdown.

Файлы идентифицируются по SHA-256 содержимого. Повторно выбранный документ не
хранится второй раз, а подключается к нужному чату.

## Архитектура

Основные компоненты:

- `LauncherActivity` — выбор сценария;
- `MainActivity` — фото, распознавание и экспорт Excel;
- `RagWorkspaceActivity` — список независимых RAG-диалогов;
- `RagDocumentsActivity` — подключение и удаление документов;
- `RagChatActivity` — история сообщений и локальная генерация;
- `DocumentTextExtractor` — извлечение текста из PDF/DOCX;
- `LocalRagIndex` и `MultiDocumentRagIndex` — поиск релевантного контекста;
- `RagStore` — файловое хранение документов, связей и сообщений;
- `MarkdownText` — безопасная базовая разметка ответа;
- `WorkbookWriter` — точечное изменение Excel-шаблона.

Подробности приведены в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) и
[docs/RAG_PIPELINE.md](docs/RAG_PIPELINE.md). Пошаговая публикация исходников
описана в [docs/GITHUB_UPLOAD.md](docs/GITHUB_UPLOAD.md).

## Сборка

Требования:

- Android Studio с JDK 17+;
- Android SDK 37;
- Android 12+ для запуска приложения;
- модель `gemma-4-E2B-it.litertlm`.

Модель весит около 2,59 ГБ и не хранится в GitHub. Перед сборкой положите её по
пути:

```text
app/src/main/assets/gemma-4-E2B-it.litertlm
```

После этого выполните:

```bash
./gradlew testReleaseUnitTest assembleRelease
```

APK появится в `app/build/outputs/apk/release/`.

## Ограничения

- один документ — до 100 МБ;
- PDF — до 500 страниц;
- извлечённый текст — до 5 000 000 символов на документ;
- сканированные PDF без текстового слоя не распознаются;
- PDF с паролем не поддерживаются;
- поиск лексический, без embedding-модели и векторной базы;
- APK со встроенной Gemma занимает около 2,65 ГБ и неудобен для распространения
  через мессенджеры и некоторые загрузчики.

## Конфиденциальность

Приложение запрашивает только разрешение камеры. Документы и результаты находятся
во внутреннем хранилище Android. Текст документа в prompt явно трактуется как
данные, а не как инструкции для модели.
