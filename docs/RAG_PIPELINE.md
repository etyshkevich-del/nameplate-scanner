# Локальный RAG-пайплайн

## 1. Извлечение

- PDF: PdfBox-Android читает текст постранично и добавляет маркер `[Страница N]`.
- DOCX: `ZipInputStream` находит `word/document.xml`, а `XmlPullParser` извлекает
  текст, абзацы, переносы и табуляцию.

Лимиты применяются во время чтения, чтобы не удерживать заведомо слишком большой
документ в памяти.

## 2. Разбиение

`LocalRagIndex` нормализует пробелы и создаёт чанки примерно по 1250 символов с
перекрытием около 180 символов. Перекрытие уменьшает вероятность потерять ответ
на границе двух чанков.

## 3. Признаки и поиск

Для документа строятся:

- нормализованные слова;
- четырёхсимвольные граммы для частичных совпадений;
- частоты признаков в каждом чанке и по коллекции.

Запрос расширяется небольшими группами синонимов. Итоговый балл основан на BM25,
а точное совпадение длинной фразы получает дополнительный вес. Для запросов на
краткое содержание предусмотрен возврат начальных чанков.

`MultiDocumentRagIndex` выполняет поиск в каждом подключённом документе, объединяет
результаты и сохраняет имя документа и номер исходного фрагмента.

## 4. Генерация

В prompt передаются вопрос, до шести найденных фрагментов и несколько последних
реплик диалога. Модель должна отвечать только по контексту и указывать источники в
формате `[Документ «имя», фрагмент N]`.

Текст документа помечается как данные. Инструкции, обнаруженные внутри документа,
не должны изменять системные правила ответа.

## 5. Ограничения подхода

Это лексический RAG, а не semantic/vector RAG. Он хорошо работает при совпадении
терминов и близких словоформ, но хуже на полностью перефразированных вопросах.
Следующий архитектурный шаг для смыслового поиска — отдельная локальная embedding-
модель и векторный индекс.
